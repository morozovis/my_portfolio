Log Analyzer

Bash-скрипт для быстрого анализа лог-файлов: подсчёт событий по уровням важности (ERROR/WARNING/INFO), выявление наиболее часто повторяющихся ошибок и предупреждений, вывод контекста вокруг проблемных записей.

## Что делает скрипт

- Проверяет корректность входных данных (аргумент передан? файл существует?) и завершается с разными кодами ошибок в зависимости от причины
- Считает количество строк ERROR, WARNING, INFO
- Выводит предупреждение ("ALARM"), если количество ERROR или WARNING превышает заданный порог
- Показывает общее количество строк в файле
- Находит самые часто повторяющиеся строки среди ошибок и предупреждений
- Выводит контекст (несколько строк до и после) вокруг ERROR/WARNING записей

## Использование

./analizator_log.sh /path/to/logfile.log

Если аргумент не передан или файл не найден, скрипт выведет понятное сообщение об ошибке и завершится с соответствующим кодом:

| Код выхода| Причина                          |
|-----------|----------------------------------|
| 0         | Успешное выполнение              |
| 1         | Не передан аргумент(путь к файлу)|
| 2         | Указанный файл не существует     |

## Использованные инструменты и подходы

- `grep -c` — подсчёт совпадений
- `grep -E` — поиск по нескольким паттернам через регулярное выражение
- `grep -A/-B` — вывод контекста вокруг найденных строк
- `sort` / `uniq -c` — подсчёт частоты повторяющихся строк
- `wc -l` — подсчёт строк без побочного вывода имени файла (через `<` вместо передачи файла аргументом)
- `mktemp` — безопасное создание временного файла с уникальным именем (без риска конфликта при параллельном запуске)
- Условия `[[ ]]` и `(( ))` — проверка аргументов и сравнение чисел
- Разные коды выхода (`exit 1`, `exit 2`) для разных типов ошибок — чтобы вызывающий скрипт мог различить причину сбоя

## Ограничения / что можно улучшить

- Уровни логов (ERROR/WARNING/INFO) сейчас жёстко заданы в коде — можно вынести в аргументы для универсальности
- Порог "ALARM" (сейчас 5) можно сделать настраиваемым параметром запуска
- Формат лога предполагается текстовым построчным — для JSON-логов потребуется другой подход (например, `jq`)
